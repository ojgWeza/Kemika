# CLAUDE.md — Kemika

This file orients a fresh Claude Code session working on this repo. Read
`CONSTITUTION.md` and `TODO.md` too — this file is "how to work here," those two are
"what this project is and what's left."

## What this is

A Unity 2D mobile game (iOS + Android) teaching analytical chemistry through hands-on lab
interaction. Full context: `CONSTITUTION.md` § 1.

## The one rule that overrides every other design instinct

**Law 1 — "No result without action."** Before adding any feature that reveals a color,
precipitate, value, or piece of chemistry information to the player: trace exactly which
manual player action causes it. If you can't point to a drag/drip/pour/observe/record
action that directly and exclusively triggers it, the feature is wrong as designed, not
just as implemented. This is the single most-violated-by-default instinct when building
UI in Unity (it's very easy to just reveal a result on `Start()` or on a `OnClick` that
doesn't correspond to an in-fiction action) — actively resist it.

## Architecture map

See `CONSTITUTION.md` § 3 for the full breakdown. Short version:

- `Kemika.Data` — `ScriptableObject` data: `IonSpecies`, `Reagent`, `Reaction`. For now,
  slice content is built via `.Create(...)` static factories in code
  (`SliceBootstrap.BuildChlorideVsSilverNitrateReaction()`), not hand-authored `.asset`
  files — those are fragile to create outside the Editor. Once real content authoring
  starts in the Editor, `.asset` files created there via `[CreateAssetMenu]` are fine and
  preferred over more code-factories.
- `Kemika.Interaction` — input handlers. `DropperDragHandler` is the only thing allowed
  to call into a mode controller's drip method.
- `Kemika.Modes` — `PracticeModeController` today. `ChallengeModeController` doesn't
  exist yet; don't add it before Practice Mode has real mastery-threshold tracking to
  gate it on (see `TODO.md`).
- `Kemika.Localization` — `LocalizedStrings`, a plain bilingual map. Add new UI text here,
  not as string literals in UI code, even if only the English half is filled in yet.
- `Kemika.Bootstrap` — `SliceBootstrap` builds UI procedurally at runtime via
  `[RuntimeInitializeOnLoadMethod]`. This exists because the project was scaffolded from
  a remote session with no Unity Editor access, so no `.unity` scene could safely be
  hand-authored. Once a real scene exists and scene-based content authoring is normal,
  new features don't need to follow this runtime-construction pattern — building UI in
  the Editor and referencing it via serialized fields is the normal/preferred Unity way
  from that point on. Don't keep extending `SliceBootstrap` indefinitely.

## Working conventions (mirrors prayer-qibla-app where applicable)

- **Repo docs (this file, `CONSTITUTION.md`, `TODO.md`, commit messages, code comments)
  are in English**, even if the working conversation with the user is in Arabic. Don't
  mix languages into project files. (User-facing in-game strings are the one deliberate
  exception — see `Kemika.Localization`.)
- **Git workflow: one branch per feature**, merged once verified. Don't commit directly
  to `main`/`master` as the default without the user asking for that explicitly.
- **Update `TODO.md` as soon as something is done** — move it into "Done," don't leave
  status ambiguous. Same for `CONSTITUTION.md` § "Settled feature decisions" whenever a
  design question gets resolved — don't make a future session re-litigate it.
- **Comments explain WHY, not WHAT.** A hidden constraint, a non-obvious Unity gotcha, a
  workaround for a specific bug — not a restatement of the code.
- No default "AI-generated" look: no unexamined `Color.magenta`/pure-black-on-white,
  no placeholder Lorem Ipsum left in shipped-looking UI. Placeholder art for the
  prototype is fine and expected (see `CONSTITUTION.md` § 6) — placeholder *copy* is not.

## Known Unity-specific gotchas in this repo

- `Packages/manifest.json` and `ProjectSettings/ProjectVersion.txt` were hand-written,
  not generated by Unity Hub. If Package Manager throws resolution errors on first open
  that don't just auto-resolve, the safe fix is: create a throwaway empty 2D project via
  Unity Hub's own wizard elsewhere, then copy its `ProjectSettings/` and
  `Packages/manifest.json` over these ones (keeping `Assets/`), rather than hand-editing
  version numbers by guesswork.
- No `.unity` scene is committed. See `TODO.md` "First local setup" for the one-time
  `File → New Scene → Save` step this requires, and commit the resulting scene (+ its
  `.meta` file) once created so this stops being a repeated step.
- Arabic strings exist in `LocalizedStrings` but will render incorrectly with the
  built-in legacy `UI.Text` component (no bidi/glyph shaping). Don't assume switching
  `LocalizedStrings.Current` to `Language.Arabic` produces correct-looking Arabic yet —
  see `CONSTITUTION.md` § Known gaps.
- The drag interaction (`DropperDragHandler`) uses the legacy `StandaloneInputModule`,
  not Unity's newer Input System package (not installed, to keep `manifest.json`
  minimal/low-risk — see `CLAUDE.md`/`CONSTITUTION.md` on hand-written package files).
  If a future change adds `com.unity.inputsystem`, this needs to move to
  `InputSystemUIInputModule` and the project's "Active Input Handling" setting reviewed.
